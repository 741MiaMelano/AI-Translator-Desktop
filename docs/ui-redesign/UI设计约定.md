## 1. 这份文档的地位

已归档的前端替换材料记录了“把旧前端整体替换掉”这一阶段，它已经完成了历史任务。但真实桌面走查暴露出：那套规范把界面按**后端技术模块和验收清单**组织，而不是按**用户任务**组织，结果产生了三处重复导航、一条走不通的转写流程、和一整层被丢掉的操作能力。

本文是界面结构的新权威。它只管**信息架构、布局、操作逻辑、文案分层**。它不改后端，也不改九套皮肤的美术语言。

权威顺序（不变）：

1. **后端真实可执行能力决定功能是否存在。** 界面不得承诺后端没有的能力，也不得隐藏后端已有的用户能力。
2. **`DESIGN.md` 决定美术、材质、动效、音效、九套皮肤和交互语言。**
3. **本文决定信息架构、布局、阶段流程和文案分层。** 与已归档的前端替换材料冲突时以本文为准。
4. 本文没有规定的，按 `DESIGN.md` 和现有组件树的既有做法延续。

## 2. 两条硬约束

### 2.1 后端功能不受影响

本文所有改动都在**编排层和展示层**：改的是"哪些后端调用、按什么顺序、在哪个位置、配什么文案暴露给用户"。

**不允许**：改 IPC 契约（`src/contracts/desktop-api.ts`）、改 preload/main 的方法签名、改后端服务、改数据形状、改持久化 schema、改能力 ID。

**允许且鼓励**：把多个后端调用编排成一次用户可理解的流程；把埋起来的能力提到可达位置；改变调用的触发位置和确认方式。

判据：任何一次界面改动之后，`src/contracts/desktop-api.ts` 的 diff 必须为空。

### 2.2 九套皮肤的风格与语言不受影响

`DESIGN.md` 第 377 行的 **Shared Skeleton Rule** 已经规定了正确的分工：

> Navigation, route order, editor columns, segment selection, QA language, Action Dock, Command Bar, data, copy hierarchy, and gating placement stay **identical across all nine worlds**; only tokens, materials, geometry, and motion may vary.

所以"九套皮肤不受影响"的正确含义**不是**"结构不能改"，而是"**结构改动必须对九套一视同仁，且只能通过 token 表达材质差异**"。

## 3. 九皮肤实现约定

### 3.1 为什么改结构是安全的

皮肤是 **token 作用域**，不是选择器作用域：

```css
:root {                     /* 皮肤无关：间距、动效、层级 */
  --space-1..6; --ease-out; --motion-fast/panel/route; --z-dock..toast;
}
[data-theme="brass"]  { --canvas --surface --text --line --accent --panel-r --overlay-shadow --focus --font-ui ... }
[data-theme="relay"]  { 同一批变量，不同材质 }   /* ×9 */
```

因此：**任何用这批 token 拼出来的新结构，九套皮肤自动正确。** 每套皮肤额外的 26–80 条 `[data-theme=...]` 规则只负责**签名几何**（票券穿孔、叠印偏移、机架端子、窑变印记…），不负责基础布局。

### 3.2 新增节点的规则

1. 新节点的所有颜色、圆角、边框、阴影、字体**必须**走 token（`var(--surface)` / `var(--line)` / `var(--accent)` / `var(--panel-r)` / `var(--overlay-shadow)` / `var(--font-ui)`…）。禁止硬编码色值。
2. 间距只用 `var(--space-1..6)`；动效时长只用 `var(--motion-*)`；层级只用 `var(--z-*)`。
3. 九套共享同一套语义 class 名和同一套 DOM 结构。**不允许**给某一套皮肤单独换结构。
4. 只有签名几何可以按皮肤分支，且必须写在 `[data-theme=...]` 块里。
5. 焦点指示统一走 `:focus-visible { outline: 2px solid var(--focus); outline-offset: 3px }`，不得移除。

### 3.3 已存在但未接线的样式（优先复用，不要重画）

`prototype.css` 里已经写好了九皮肤完备的样式，但 `production.css` 里规则数为 0，生产组件树从未挂载：

| class | prototype.css | production.css | 用途 |
|---|---|---|---|
| `.command-layer` / `.command-panel` | 1 / 6 条 | 0 | 全局命令面板（Ctrl+K） |
| `.shortcuts-panel` | 23 条（含主题作用域） | 0 | 快捷键速查（?） |
| `.action-dock` | 6 条 | 0 | 编辑器底部固定操作坞 |
| `.inspector-panel` | 12 条 | 0 | 检查器 |

实施这些功能时**必须先复用已有样式**，只补组件与接线。不得另画一套视觉。

## 4. 顶层信息架构

侧栏固定 4 项：

```
工作台     进入 / 继续
项目       全部项目 · 任务 · 归档 · 回收站
资源库     术语 · 风格 · 字幕样式 · 导出预设
系统       能力 · Provider · 模型 · 存储 · 备份 · 诊断 · 版本
```

**核心规则：凡是需要"先选一个项目"的界面，都不进侧栏。** 它们是项目内的阶段。

理由：旧的 6 项侧栏里，"素材与识别"和"字幕编辑与校对"离开项目就没有意义——点进去只会得到一个"请先选个项目"的中转页（`MediaPage.tsx` 的 `MediaLanding`、`App.tsx` 的 `EditorShortcut`）。它们不是功能，是为了填满侧栏而存在的空转页；代价是侧栏 active 判断退化成四层三元表达式。

`/projects/:id/media`、`/projects/:id/editor/:lang`、`/projects/:id/deliver`、`/projects/:id/settings` **全部保留**，但语义从"独立页面"变为"深链接 + 阶段选择器"。刷新与恢复行为不变。

## 5. 项目工作区

### 5.1 一条导轨，五个阶段

`DESIGN.md` 第 367 / 375 行：五个阶段占**一条**横向导轨，当前阶段解析为**一个**全宽下一步面板；所有阶段可见，但只有一个拿 accent，只有一个面板拿主操作。

阶段名统一为五个用户任务名：

```
① 导入   ② 转写   ③ 翻译   ④ 校对   ⑤ 交付
```

废止两套并行词汇（旧 `stage-rail` 用 `素材/字幕/翻译/QA/交付`，旧 `ProjectWorkspaceNav` 用 `项目概览/素材与识别/字幕编辑与校对/交付`）。

"项目设置与资产"**不进阶段编号**，作为项目标题旁的次级齿轮入口。

**"翻译"阶段目前只有状态、没有目的地**：它的配置界面属于 B2 工作项。在那之前它仍占据导轨的第 3 格作为进度指示，点不动并说明"在导入阶段发起"——保持五步模型完整，同时不制造假入口。

**实现约束：导轨不得改变 `li` 的子元素结构。** `prototype.css` 里有 20 多条 `[data-theme=...] .stage-rail li > span` / `li > i` 规则承载 ticket / proof / fold / strata / signal / celadon / relay 七套皮肤的签名几何（方形端子、叠印偏移、折面、切面、总线、水线）。把 `span`/`strong` 包进按钮会让这些规则全部失效。正确做法是叠加一个 `position: absolute; inset: 0` 的透明按钮作为点击与焦点目标。同理，不可达阶段**不要**再渲染一个 `span` 占位——`.stage-rail li > span`（特异性 0,1,2）会压过单类名，把它画成第二个阶段圆点。

纯字幕项目的"转写"显示为 `不适用 · 已有字幕` 的完成态，**不隐藏**——保持"一共五步，我在第几步"的心智模型完整。

### 5.2 阶段就地切换

```
┌──────────────────────────────────────────────────────────────────┐
│ 项目标题              源语言 → 目标语言        ●状态标签    [⚙]  │  ← 常驻
├──────────────────────────────────────────────────────────────────┤
│  ①导入 ──✓── ②转写 ──✓── ③翻译 ──✓── ④校对 ●── ⑤交付 ○         │  ← 常驻，唯一
├──────────────────────────────────────────────────────────────────┤
│                                                                  │
│   〔阶段工作区 —— 内容随选中阶段变化，页面不跳转〕                 │
│   每个阶段自带它唯一的主操作面板                                   │
│                                                                  │
└──────────────────────────────────────────────────────────────────┘
```

**导轨切换的是这一页里的工作区，不是路由跳页。** 项目头部与阶段导轨跨阶段常驻挂载，实现上用 React Router 的布局路由 + `<Outlet/>`，因此外壳不随阶段重新挂载。

**"下一步"面板属于阶段体，不属于外壳。** `DESIGN.md` 第 367 行的原文是"当前这一步解析为一个全宽的下一步面板"——它描述的是**当前阶段**的主操作，不是一个跨阶段的全局提示。放进外壳会产生矛盾：用户在转写阶段却看到"下一步：进入校对"。所以每个阶段体自带它唯一的主操作面板，"One Current Stage Rule"由此自然满足。

必须满足：

- 外壳（项目标题、状态、阶段导轨）不随阶段重新挂载；未保存的人工修改因为写在共享的 WorkspaceContext 里，切换阶段不会丢。
- 任何阶段内都不出现"返回项目概览"按钮（因为从未离开）。
- 键盘可遍历导轨，当前项 `aria-current="page"`。
- 阶段不可用时（如"先生成目标字幕轨"）仍留在导轨上作为进度指示，显示原因而不是消失。

> **尚未做到**：阶段体本身仍会随路由卸载重建，所以媒体播放位置、选中段和滚动位置目前不跨阶段保留。要做到需要把这些局部状态上提或写进 URL，属于独立工作项，不在本轮范围内——本文不把它写成已实现。

**阶段导轨上有两个不同的指示，不要混淆**：accent 圆点表示**流水线进行到哪一步**（由项目真实内容推导），下划线 + `aria-current` 表示**你正在看哪一个阶段**。两者可以不同，例如流水线停在"转写"而你正在看"导入"。

**唯一例外：校对阶段接管整个视口**，侧栏自动压成 72px Compact Rail（`DESIGN.md` 第 369 行本来就要求），只保留一条纤细项目条。理由：这是唯一会连续停留 30 分钟以上的阶段。

### 5.3 五个阶段的内容

#### ① 导入

源文件、媒体信息、源轨列表与活动轨标记。操作：导入字幕文件、导出源字幕、重新关联媒体、重新探测。

> 前两项对应的后端能力当前几乎无前端入口，本阶段负责把它们提出来。

#### ② 转写

**一个主操作，不是四个同级按钮。**

```
转写 · 把音频变成字幕

  音轨   [ 音频 #1 · 2ch · 48kHz ▾ ]
  语言   [ 自动检测 ▾ ]
  设备   AUTO · 允许回退 CPU                        〔详细〕

           ┌─────────────────┐
           │   开始转写  →   │        ← 唯一主操作
           └─────────────────┘
  ▸ 分步执行（识别 / 分段 / 检测语言 / 启用轨道）    ← 进阶逃生口

  运行中：  ① 识别 ████████░░  ② 分段 ○  ③ 启用为源轨 ○
```

- 主操作按序调 `asr.transcribe → asr.segment → activateSourceTrack`，带可见子步骤进度。
- 语言区域检测**只在识别结果真的检出混合语言时**作为后续步骤出现。
- `分步执行` 展开后是原来那四个按钮，原样保留，给进阶用户和排障用。
- **后端调用与参数完全不变**，改的只是编排顺序与呈现。
- **主操作面板排在素材面板之前**，且这个阶段的画面收进折叠区（默认关闭）。转写只依赖音轨；判断"是不是这条素材"靠时间轴听和元数据核对，不靠看画面。时间轴与元数据条留在折叠区外面，`<video>` 保持挂载（用 `display:none` 而非条件渲染），折叠时音频仍可播放。

#### ③ 翻译

翻译此前没有独立位置，散在"开始处理"自动流程和编辑器的"生成完整候选译文"两个语义不同的入口里。本阶段是它唯一的家。

内容：Provider + 模型 / 目标语言（可增删）/ 术语表选择 / 风格指南选择。

**同意方式：肯定式勾选框启用主操作**（`DESIGN.md` 第 459 行），而不是点击后弹确认框。

```
  ☑ 我确认这会向 DeepSeek 发送请求，可能产生费用
  ┌──────────────┐
  │  开始翻译 →  │      ← 勾选后才启用
  └──────────────┘
```

理由：费用必须在**点击之前**可见，而不是点了之后才被拦一下。

顺带解决术语表 / 风格指南的项目绑定此前只在"项目设置与资产"里、极易错过的问题——资源库里的资源如果没人挂上去就完全没有价值。

**"唯一的家"要当真：** Provider、模型、术语表、风格指南、目标语言这五项**从项目设置页移走**，那里只留一句去处指引。留两份等于又造一处"改了一处不生效"的困惑，也是这轮重构要消掉的同一类问题。项目设置页保留的是不属于任何单一阶段的项目默认值（源语言、本机 ASR 模型、默认导出格式、媒体复制与烧录开关）。

这一阶段的方案改动**即时写入项目**（`updateProjectConfig` / `setProjectTargetLanguages` 自带自动保存），不再要求先点一次"保存方案"——主操作前面不该还有一个隐藏的前置操作。同意勾选**每次运行后清空**：它是对这一次请求的同意，不是一个长期开关。

概览页的"开始处理"（整条自动流水线）保留，它是小白的一键路径；翻译阶段是同一件事的显式路径。两者都走后端真实调用，互不冲突（第 8 节三层策略）。

#### ④ 校对

见第 6 节。

#### ⑤ 交付

**导出选项常显，禁用时写明原因。**

```
交付

  QA 门   ✓ 已通过      0 项必须 · 26 条建议 →    ← "建议 N" 必须可点
  状态    待校对

  ┌────────────────────────┐
  │ 批准 简体中文 字幕轨   │
  └────────────────────────┘

  导出
  ⊘ 字幕文件 SRT / VTT / ASS          需先批准
  ⊘ 带字幕视频（烧录 ASS 样式）        需先批准
  ⊘ 封装软字幕视频                     需先批准
  ○ 打包项目 .zip                      随时可用
  ○ 预览最终效果                       进入预览模式
```

规则：

- **批准前必须看得见导出目的地。** 批准是不可逆的语义动作，不允许在信息更少的时候做。旧实现在批准前把整块导出区换成一个警告框，用户不知道自己将得到什么。
- **"建议 N" 必须可点**，跳编辑器并筛选建议。旧实现只把必须问题渲染成可跳转列表，导致"0 必须 + 26 建议"时用户没有任何入口。因此编辑器要接受 `?filter=issues` 与 `?preview=1` 两个入口参数。
- `人工操作` 改为 `来源`（识别生成是机器动作，不该记在人工名下）。
- QA 门、批准门、导出门的**行为不变**：必须问题未清零不得批准，未批准不得导出。
- **常显不等于"全部一起变灰"。** 打包项目不依赖批准，它必须真的可点，否则用户无法区分"这一项被门挡住"和"这一整块还没到时候"。
- **交付单本身不能换成普通面板。** `.delivery-sheet` 是九套皮肤各自的签名元件（车票盖 `DELIVERY STUB / CLEARED`、折页盖 `FULL SHEET / READY`、中继切角、青瓷内描边）。常显只允许改两件事：① 压几何（高度、内边距、印章尺寸），② 未批准时**抑制那两枚"已放行"戳记**——盖着 `CLEARED` 说"还没批准"是自相矛盾的。皮肤的底纹、切角、阴影一律不动。

## 6. 字幕编辑器

### 6.1 为什么不用四列

`DESIGN.md` 第 369 行说编辑器是"四个部分"：媒体与传输、段列表、原文译文编辑器、检查器。但它没有规定这四部分**必须是四个并排的列**——而四列在最小窗口下必然失败。

1280 宽、侧栏 202px、页面内边距 48px → 可用 1030px：

| 方案 | 媒体 | 段列表 | 编辑区 | 检查器 | 结果 |
|---|---|---|---|---|---|
| 旧实现（2 列） | 420 | ← 604 共享 → | — | 列表与编辑挤一列，**选中就重排** |
| 四列 | 300 | 250 | 200 | 280 | **编辑区 200px，全废** |

四列的根本错误是**让宽度需求最矛盾的东西沿同一维度竞争**：

| 部分 | 真正需要的维度 | 需要的频率 |
|---|---|---|
| 波形 | **宽度**（30 秒窗口在 1176px 上可读，420px 上是一团糊） | 高 |
| 视频画面 | **面积**，且只在少数时刻要 | 低 |
| 段列表 | **高度**（能看到多少行） | 高 |
| 译文输入 | **宽度** | 持续 |
| 段度量 | 很少的宽度 | 持续 |

所以这不是拖拽粒度问题，是维度分配错了。**解法：把媒体从"列"里拿出来。**

### 6.2 编辑模式（默认）

```
┌ 项目名 · 目标语言 · 自动保存        [撤销][重做][搜索替换]     ┐  42px
├────────────┬──────────────┬─────────────────────────────────┤
│ 参考 260    │ 段列表 290    │ 当前段编辑 626                  │
│ ┌────────┐ │ 022 ...      │ 原文                            │
│ │视频     │ │ 023 ...      │ 〔源文本〕                       │
│ │260×146 │ │ 024 ...  ◄   │ ─────────────────────────────   │
│ └────────┘ │ 025 ...      │ 译文                            │
│            │ 026 ...      │ ┌─────────────────────────────┐ │  448px
│ 当前段术语  │ ...          │ │〔大输入区〕                  │ │
```

**编辑器阶段必须解掉 `.page-stage` 的 1240px 上限。** `prototype.css:717` 的
`.qa-page { width: calc(100vw - var(--sidebar-w) - 28px) }` 是写给"编辑器**就是** page-stage"
那种旧结构的。编辑器现在是限宽外壳的子元素，子比父宽就会溢出——1876 窗口下编辑器右
边界到 1911，比窗口还宽 33px，内容被静默裁掉。

**段行密度要压。** `prototype.css:578` 的 `.segment-row { min-height: 91px }` 是给旧的宽
列设计的；列表现在是独立的 290px 栏、原文译文都已单行省略，91px 会让 30 段里只看得到
三四行。压到 74px 后可见行数多 25%，且只改几何、不动字号颜色边框等皮肤语言。

**校对阶段不要再出现第二个标题。** 阶段导轨上高亮的"校对"已经说明了当前位置，项目名
也在项目条上，再放一个 `<h2>字幕编辑与校对</h2>` 就是第三次重复，代价是一整行首屏高度。
工具全部收进一行。

**校对阶段必须接管视口**（`height: calc(100vh - var(--topbar-h))` + 内部滚动）。否则编辑器在 720 高的窗口里会长到 1135px，把项目头部和阶段导轨顶出视野——这不是美观问题，是导航直接消失。同时项目头部在校对阶段收成纤细项目条（隐藏描述行、标题降到 19px），因为不值得为它花掉 21% 的可用高度。

Action Dock 的定位与材质直接复用 `prototype.css` 的 `.action-dock`（`position: fixed`、九皮肤 dock 材质、`1fr auto 1fr`），只需补内部排版；不要另写一套定位。

关键决定：

1. **视频常态只负责"瞥一眼"**（260×146）。真要看大用预览模式。
2. **波形拿全宽底条**，宽度从 420 涨到 1176（2.8×）。这是本次交换的主要收益。
3. **"检查器"这一列拆掉。** 它的内容本来是两类被硬塞在一起的东西：
   - 当前段度量（阅读速度 / 字符数 / 锁定 / 候选数）→ 移到译文框下方紧凑度量条，紧贴编辑区
   - 整轨进度（校对进度 N/M）→ 并进 Action Dock
   拆完之后不需要第四个并排部分，左栏也得以收窄。
4. **左栏是"参考栏"**：画面 + 当前段术语（可点插入）+ 样式入口。原型的左栏正是这个结构。
5. **段列表独立成栏，选中不再重排整列**。这在 30 段无所谓，在 200/2000 段是决定性的。
6. **Action Dock 常驻底部**（`DESIGN.md` 第 453 行）：问题导航 + 一句人话 QA 摘要 + 唯一批准动作。旧实现把批准放在页面顶部 header，离视线最远。
7. **≥1600px 时**编辑区内原文/译文改左右并排（这正是 Proof / Inkwhite 两套皮肤的 dual-column 语言想要的形态）。

### 6.3 预览模式

`V` 进 / `Esc` 出。**不是"媒体列变宽"，是一个独立设计的模式。** 因为放大时用户做的事变了——他在**看效果**，不在**改字**，此时段列表和术语栏都是干扰。

```
┌ 项目名 · 目标语言                        预览模式 · Esc 退出 ┐
├────────────────────────────────────────┬───────────────────────┤
│                                        │ 项目字幕样式           │
│        画面 697×392（高度约束）          │ 影响全部字幕与导出      │
│                                        │ ─────────────────     │
│     ┌──────────────────────────┐       │ 字号   ───●───        │
│     │  〔真实样式的字幕叠加〕    │       │ 颜色   ■              │
│     └──────────────────────────┘       │ 描边   ──●────        │
│                                        │ 位置   [上][中][下]   │
│                                        │ 字体   ▾              │
│                                        │ 排布   ▾              │
├────────────────────────────────────────┴───────────────────────┤
│ 〔全宽波形〕  ◄◄ ▶ ►► 0.75× 循环本段                          │
├────────────────────────────────────────────────────────────────┤
│ 024  00:01:23,480  [〔可原地改字〕            ]  ◄  ►         │
├────────────────────────────────────────────────────────────────┤
│ ◄ 上一问题  8/30 已校 · 0 必须 · 26 建议  下一问题 ► [批准并交付]│
└────────────────────────────────────────────────────────────────┘
```

**实测值**：1440×900 舞台 997×431、样式面板 300；1280×720 舞台 880×266、样式面板 260（媒体查询收窄）。两档文档溢出均为 0。

关键决定：

1. **画面是高度约束的，所以右侧 300px 样式面板几何上是免费的**（收起它画面也不会变大，只会更居中）。这一点在 16:9 类窗口下普遍成立，包括最大化到 1920×1080。
2. **必须标注"项目字幕样式 · 影响全部字幕与导出"。** 样式写的是项目配置，导出 ASS 与烧录视频用同一份。不标注用户会以为在调当前这一行。
3. **样式只保留一个家。** 编辑模式左栏的 `[字幕样式→]` 不再展开面板，而是直接进预览模式。理由：调样式必须看得见效果，而只有预览模式看得见；旧实现让用户在 420px 画面上调字号，调完不知道对不对。

   **但预览模式必须对所有项目开放，不能只给有视频的项目。** 样式同样写进 ASS 字幕导出，纯字幕和纯音频项目一样需要调。把入口限制成"有视频才显示"会直接拿掉这两类项目的样式访问权——那是回归而不是收敛。没有画面比例时，舞台退回 16:9 空画布并照常渲染字幕叠层；否则舞台会横向塌成 0 宽，字幕无处可显示。
4. **底部保留单行当前段（可原地改字）+ Action Dock**，所以预览模式不是死胡同——可以一路 `►` 走下去看效果，发现问题原地改。
5. **`◄ ►` 默认按"有问题的段"步进**，`Shift+◄►` 按全部段。进预览的人通常在做整体验收，逐条走 200 段没意义，走 26 条建议才有意义。
6. 交付阶段的"预览最终效果"进入同一个模式。同一界面服务两个场景，不另做导出预览页。

### 6.4 离散布局状态

大的布局决策做成**有设计的离散态**，而不是一条永远不对的分隔条：

| 键 | 状态 | 编辑区宽度（1280 下） |
|---|---|---|
| — | 三栏 + 波形条 | 626 |
| `I` | 收起参考栏 | **886** |
| `W` | 收起波形条 | 626（工作区高度 +96） |
| `I`+`W` | 纯文字 | 886 宽 / 544 高 |
| `V` | 预览模式 | — |
| `F` | 专注模式（只留当前段） | 全宽 |

段列表 ↔ 编辑区之间的分隔条**保留**（进阶用户需要），但它只在这两者之间微调，不再承担"媒体 vs 一切"的调停职责。

### 6.4b 两种拆分不是同一件事

`src/domain/segment-timeline.ts` 有两个拆分函数，此前界面只接了其中一个，结果"把长字幕切成两句"这件事在产品里做不到。

| 命令 | 切什么 | 界面位置 | 用途 |
|---|---|---|---|
| `split` | **只切时间**，后半段文字为空 | 时间轴页 · `中点拆分（只切时间）` | 给漏掉的台词腾出一格 |
| `split_text` | 时间 + 译文 + 原文一起切 | 译文框下方 · `按光标拆分` | 一句太长，就地切成两句 |

规则：

- **按光标拆分必须挨着译文框。** 该在哪儿切，只有正在读这句译文的人知道；把它放进时间轴页等于要求用户先离开文字再回来。
- 时间码由**播放头**决定；播放头不在这一段内时，退回按光标比例取一个段内时间点（domain 已实现，界面不要另算一套）。
- 原文按同一比例在**最近的自然断点**切开（标点/空白），保证两行都能独立使用。
- **调用方自己提供 `idFactory`。** 拆分会用两个新 id 替换当前段，界面必须在拆完后停在左半段——否则选中的 id 消失，编辑器退回第一段，用户被弹到列表顶端。
- 两个按钮的名字必须把语义差别说出来；`中点拆分` 这个旧名字没有透露"后半段是空的"。

### 6.5 退化情况

| 项目类型 | 表现 |
|---|---|
| 纯音频 | 参考栏无画面，只有术语；波形条即全部媒体面 |
| 纯字幕 | 参考栏只有术语；波形条自动收起，工作区拿满 544px |
| 媒体缺失 | 参考栏显示重新关联入口；不伪造播放器画面 |

## 7. 全局命令层

### 7.1 命令面板

顶栏的 `topbar-spacer` 空白区放搜索/命令入口，`Ctrl+K` 打开面板。

```
AI TRANSLATOR  [⌕ 搜索项目或命令   Ctrl K]   ● 桌面服务已连接  [A·黄铜机台▾]  – □ ×
```

四组内容，按优先级：

1. **建议操作** — 由真实状态算出：继续「某项目」·停在某阶段 / 处理下一处必须问题 / 开始新翻译 / 配置翻译服务（未配置时）
2. **项目** — 标题 + 文件名模糊搜索，跳到它当前所在的阶段
3. **前往** — 4 个顶级 + 批量处理 / 回收站
4. **操作** — 切换音效 / 快捷键速查 / 外观与声音 / 翻译 Provider / 本机语音识别 / 模型与文件位置 / 应用备份与脱敏诊断包

> 原先这一组里还列了"检查更新"。后端没有对应的 IPC，命令面板不能摆一个点了没反应的条目，所以删掉；等后端真有这个能力再加回来。为了让"导出诊断包"能直接落到那张卡片上，设置页接受 `?tab=` 参数。

第 ④ 组的设计意图：**命令面板是把当前无前端入口的后端能力接回来的最便宜方式**，不必为每个能力单开页面。第 ① 组同时服务小白——它回答的是"我现在该干什么"。

`Esc` 关闭并归还焦点。样式复用 `prototype.css` 的 `.command-layer` / `.command-panel`。

### 7.2 键盘

`?` 打开快捷键速查面板，内含三套预设切换，面板始终显示当前生效的那套，选择持久化到 `localStorage`（与主题同机制）。

键位表的唯一事实来源是 `src/frontend/shortcuts.ts`，速查面板和编辑器绑定都读它。下表是核实后的定稿：

| 动作 | 现代效率流 | 剪辑师流 (FCP) | 传统字幕流 (Aegisub) |
|---|---|---|---|
| 播放/暂停 | `Space` | `Space` | `Space` |
| 上/下一段 | `J` / `K` | `↑` / `↓` | `Z` / `X` |
| 穿梭倒/停/进 | — | `J` / `K` / `L` | 停止 `H` |
| 时间轴步进 | `Alt+←→`（起点）`Alt+Shift+←→`（终点），100ms | 同 | 小键盘 `4/6`（起点）`7/9`（终点），**10ms** |
| 循环本段 | `R` | `Ctrl+L` | `R` |
| 提交并跳下一条 | — | — | `Enter` |
| 采纳候选 | `Ctrl+Enter` | `Ctrl+Enter` | `Ctrl+Enter`※ |
| 收参考栏 / 收波形 | `I` / `W` | `I`※ / `W`※ | `I`※ / `W`※ |
| 预览模式 | `V` | `Ctrl+Shift+F` | `V`※ |
| 专注模式 | `F` | — | — |
| 撤销 / 重做 | `Ctrl+Z` / `Ctrl+Y` | `Ctrl+Z` / `Ctrl+Shift+Z` | `Ctrl+Z` / `Ctrl+Y` |
| 命令面板 / 速查 | `Ctrl+K` / `?` | 同 | 同 |

预设存在的理由是有真冲突：现代流的 `J/K` 是上/下一段，剪辑师流的 `J/K/L` 是穿梭播放，没有预设只能二选一。

**参考应用的键位一律照抄真实默认值。** 来源：Aegisub 随程序编译进去的 `src/libresrc/default_hotkey.json`；剪辑师流用 Final Cut Pro 官方快捷键文档，外加 Adobe 明确记载的 J/K/L 穿梭（Premiere 的其余默认键在 Adobe 现行文档里查不到，所以这一套按 FCP 定名、按 FCP 定键）。

**参考应用根本没有这个功能时，不编一个假键位冒充它。** Aegisub 源码里既没有循环播放命令、也没有全屏预览命令；FCP 没有"参考栏/波形条"这种概念。这些行沿用本应用自己的键，并在速查面板里以 `·`（上表的 ※）标出"参考应用没有对应默认键"。名不副实比没有预设更糟。

注意 Aegisub 的时间轴步进就是 **10ms**（`audio_timing_dialogue.cpp`），不是 100ms。预设要还原的是这种细节，不只是键帽。

**焦点规则（必须按预设走，不能全局一套）**：

- 无修饰键的单键（字母、小键盘）只在焦点**不在**文本输入内时生效。
- 带修饰键的组合（`Ctrl+*` / `Alt+*` / `Shift+*`）始终生效。
- **例外**：Aegisub 预设的 `Enter`（提交并跳下一条）**只在输入框内**生效——那是它的全部意义。

第三条不是可选的：去掉它以后，在译文框里打 `JKI` 会一个字符都进不去，全被当成命令吃掉（已用 E2E 反向验证）。

## 8. 小白 / 进阶分层策略

目标是"同时面向小白与进阶用户"。**不采用分叉流程**（双倍维护 + "我在哪个模式"的困惑），改用三层：

| 层 | 做法 |
|---|---|
| **路线相同** | 所有用户都走 导入→转写→翻译→校对→交付，不分叉 |
| **每阶段一个主操作 + 一个分步逃生口** | 主操作完成整个阶段（小白路径）；`分步执行` disclosure 暴露单个后端操作（进阶路径） |
| **一个密度开关** | `简单 / 专业`，只控制技术读数的显示密度 |

`简单` 隐藏：检查点 / 重试次数、探测器版本、codec 参数、量化方式、设备策略细节、资源 revision 号、受信模型清单。
`专业` 全显，且 `分步执行` disclosure 默认展开。

开关放侧栏底部，与音效/收起并列，`localStorage` 持久化。

**硬约束：密度开关绝不隐藏任何"门"。** 同意勾选、QA 阻断、批准顺序、删除确认在两种模式下**完全一致**。小白不可能因为用了简单模式而失去任何能力或保护。

## 9. 能力分级

契约里的四个能力 ID（`translation` / `asr` / `subtitle_export` / `video_export`）**不变**，本节只改分组与文案。

旧做法把四项平权展示，导致"只翻译字幕文件"的用户永久看到一个红点和"N 项核心能力需处理"——而他根本不需要 ASR。

改为按**什么时候需要它**分级：

```
现在需要
  ● 翻译服务      〔状态〕                                   [管理]

按需启用
  ○ 语音识别      未安装模型 · 只在处理没有字幕的视频/音频时需要 [安装]
  ● 字幕导出      本机始终可用
  ● 视频后处理    烧录或封装视频时需要
```

规则：

- 侧栏状态**只在阻塞当前项目的下一步时才报警**，否则显示 `就绪`。
- 每项不可用的能力必须有一句"**什么时候需要它**" + 一个真能到达修复位置的按钮。
- 不得出现无意义的比例（如 `4/5 项能力可用`）。用户需要知道的是"影响不影响我现在这件事、怎么恢复"。

那句"只在处理没有字幕的视频/音频时需要"是全应用单位价值最高的一句文案——它把一个吓人的红点变成一个知情的选择。

**分级由真实项目状态推导，不是一张写死的表。** 语音识别只有在手头**真有一个需要它的项目**（有媒体但还没有可用源字幕）时才升到"现在需要"；否则它待在"按需启用"，侧栏也不会为它报警。实现集中在 `src/frontend/capabilities.ts`，侧栏、工作台状态条、系统页、命令面板都读同一份，避免几处口径互相矛盾。

### 10.2 删掉自证句

以下这类句子是写给验收人的，不是写给用户的。它们占版面、增加阅读负担，而且对小白显得可疑（"为什么要强调不伪造？"）：

- ~~"界面不会制造排队数量或静态进度。"~~

- ~~"阶段不会由 UI 任意改写。"~~

## 13. 验收基线

每一项界面改动完成后必须过：

**功能与回归**

- `pnpm run check` 退出码 0。
- 相关 E2E 退出码 0。
- `src/contracts/desktop-api.ts` diff 为空。

**视口与缩放**

- 1440×900（正式基准）、1280×720（最小窗口）、Windows 200% 缩放。
- **宽窗口也必须验**（1600、1920）。限宽外壳里套一个按 `100vw` 算宽度的子元素时，溢出量随窗口变宽而变大——只测最小窗口会漏掉。
- CSS 下限 1040px（`prototype.css` 的 `body { min-width: 1040px }`）。

**水平溢出必须按元素边界查，不能查 `document.scrollWidth`**

`body { overflow-x: hidden }` 会把水平溢出**静默裁掉**：`scrollWidth` 不增长、不出现滚动条，表现只是右侧内容被切断。所以断言必须遍历元素比对 `getBoundingClientRect().right > innerWidth`。

同理，只查 `button, input, select, textarea, a` 也不够——溢出的往往是 `div` / `section` 这类布局容器。参考 `e2e-fr02-core.mjs` 里跨四档宽度遍历 `.app-shell *` 的那段断言。

**结构断言不要钉在标题文案上**

编辑器已经没有独立标题（阶段导轨上高亮的"校对"就是它的名字），所以 E2E 判断"编辑器已就绪"要用 `[data-fr02-view="editor"]` 这类稳定结构标记。钉标题文案的后果有两种：删标题时测试全挂；或者更糟——源码注释里恰好出现同样几个字，静态断言假通过。

**九套皮肤**

- A–I 九套在改动涉及的界面各完成 1440×900 与 1280×720 截图对照。
- 结构、顺序、语义 class 完全一致，只有 token 与签名几何不同。

**偏好与可达性**

- 音效关闭 / 开启各验证一次；关闭时不得创建 AudioContext。
- `prefers-reduced-motion` 开启后非必要动效停止，业务状态仍可见。
- 键盘可遍历全部主流程，焦点可见，当前项有 `aria-current`。
- 普通文本对比度 ≥ 4.5:1；大号文本、UI 组件、焦点指示 ≥ 3:1。

**空态不能是死胡同。** 任何"什么都没有"的界面，它上面的主操作必须真的到得了目的地。整宽引导一度把「新建」指向了一个不渲染的编辑器——因为渲染条件写的是"这一类资源为空"，而不是"为空**且**没有草稿"。空态的判据要包含"用户刚刚做的事"。

**文字必须在自己的格子里换行。** 视口级的溢出检查看不见这一类：元素还在视口里，但 `scrollWidth` 大于 `clientWidth`，于是压到隔壁卡片上。原型的格子是按"一行短标签"排的（能力格第 4 条轨道只有 14px，留给 chevron），往里塞整句话必然溢出。改文案前先确认它落在哪条轨道上；`scripts/e2e-fr07-user-paths.mjs` 的 `assertNoTextOverflow` 按元素自身尺寸查这件事。

**已知的测试耦合**（结构改动会打破，需同步修正）

| 文件 | 规模 | 断言内容 |
|---|---|---|
| `tests/frontend-fr07-user-path-boundary.test.mjs` | 64 行 | 侧栏含"素材与识别"/"字幕编辑与校对" |
| `scripts/e2e-fr07-user-paths.mjs` | 379 行 | `project-workspace-nav` / `project-task-shortcuts` / `media-task-rail` / 侧栏标签 |
| `scripts/e2e-electron-smoke.mjs` | 1082 行 | 4 处引用"字幕编辑与校对" |

> `frontend-fr07-user-path-boundary.test.mjs` 在 `test:ui` 里，而 `test:ui` 在 `pnpm run check` 里——所以侧栏一改 `check` 就会红，直到同步修完。
>
> **修正原则：只改过期的结构断言，不删任何后端能力断言或安全边界断言**（付费确认、QA 门、人工修改保护、回收站保护）。分不清是结构还是边界时，停下来确认，不自行放宽。
